# 内容分类基础

分类系统遵循三个稳定概念：

- 内容：文章、图片和过程说明等实际数据。
- 频道：内容的大方向，目前为“工作与学习”和“生活分享”。
- 分类：频道下可新增、改名、迁移或删除的组织方式。

## 数据约束

每篇内容必须保留 `channel_id`，`category_id` 可以为空。分类被删除时，数据库通过外键将 `category_id` 设为 `NULL`，不会删除内容，也不会改变频道、草稿、发布、精选或置顶状态。

`category_id = NULL` 代表未分类内容。下一阶段的管理中心和公开页面会将它显示为系统兜底项“其他”。“其他”本身不是一条可删除的分类记录。

## 初始数据

首次迁移会创建：

- `journal`：工作记录、学习笔记
- `life`：模型手办、旅行记录、生活随笔

旧内容会自动建立对应关系，新内容由数据库触发器自动关联。初始化完成后会写入迁移标记；以后删除初始分类，服务器重启不会把它重新创建。

## 兼容策略

现有五种 `content_type`、API 地址和公开页面暂时保留。API 响应会逐步附加频道与分类字段，前端可以在后续阶段切换为动态分类，而无需一次性改写现有内容存储结构。

## 第二阶段管理能力

管理中心现已支持新增、改名、排序和删除分类，并可对单条或多条内容调整分类。跨频道转移会被拒绝且整批不写入，防止工作学习内容误入生活频道。

公开页面的分类导航来自实时配置，不再写死五个初始分类；未分类内容统一显示在“其他”。创作台仍保留五种底层内容格式，用于区分图片型内容和过程记录型内容，但发布分类可以独立选择。
